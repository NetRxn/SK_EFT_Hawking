## MAJOR CP-R1: resume must deny dispatch throughout mutation and conflict recovery

**Proposal locations:** ADR-008 lines 1026–1034; design lines 89–103. These require fresh acquire/prepare, drain, owned stop and restoration, but do not carry CP-4's explicit lease quarantine/deny-dispatch transition into resume or define when dispatch may become active again. The changed-base conflict rule blocks continuation in prose without specifying the lease state that enforces it.

**Actual source:** `controller.py:537–540` makes a prepared lease ACTIVE. `proxy.py:113–119` authorizes lease-dependent requests from the lease's ACTIVE state; the slot/lifecycle locks do not participate in that authorization. The ordinary pause helper also restarts on exceptional exit (`supervisor.py:1624–1633`). Thus an implementation can follow the stated resume sequence while leaving an ACTIVE dispatch gate during source mutation or after a merge conflict. Client-drain receipts establish completion of accounted requests, but do not themselves make the proxy deny a later request.

**Minimum correction:** specify resume as the corresponding guarded transaction on the newly acquired lease: bind its generation/current bytes and destination source, durably enter a non-ACTIVE quarantine before source mutation, and retain denial across interruption/conflict/failed restoration. Define the sole successful transition back to ACTIVE after exact resulting source and current dependency/epoch bindings, canonical backend restoration and the required loaded-runtime admission are reconciled. Use the existing lease and journal; no second dispatch/reservation mechanism. Never reuse an unconditional restoration helper that can restart a conflicted tree. Historical evidence remains historical and sourceReady remains false.

**Necessary controls:** exercise the actual proxy lease reader while resume is paused before/after restore and on merge conflict, plus interruption before successful reactivation. A sole omitted-quarantine/reactivation guard must be caught. Assert no backend rewarm on unresolved conflict and no stale journal replay over the new lease.

## MAJOR CP-R2: close the nontracked-source byte and destination-collision contract

**Proposal locations:** ADR-008 lines 987–995 and 1029–1033; design lines 42–57, 73–76 and 93–97. The design permits a nontracked entry classified as preserved source, protects committed source through a Git ref, and explicitly copies evidence. It does not explicitly map every preserved nontracked source entry to stored source bytes. A HEAD/tree ref plus a content hash cannot contain a file outside that tree. Resume similarly promises exact source restoration without specifying treatment of existing ignored/nontracked destination material.

**Actual source:** `_dirty` uses ordinary porcelain status (`controller.py:198–201`), which is not a complete ignored-file inventory. `prepare`'s reset seam is a hard reset (`controller.py:523–533`); its tracked-clean guard is not a destination-collision guarantee for ignored paths or file/directory obstructions. The new classification reader must do more than reuse `_dirty`. This is a specification gap, not an observed data-loss reproduction: no reset or merge was executed in this review.

**Minimum correction:** define the preservation receipt so every source entry is either present in the exact protected WIP tree or represented by a durable copied source payload with its path/type/byte hash. Explicitly refuse if classified source exists only as a manifest hash. Before checkpoint reset and either resume path, enumerate/reobserve the current destination and refuse a reset/checkout/merge whose tracked target would overwrite any retained nontracked/ignored entry or directory obstruction. Alternatively resolve the entry through ordinary source-safe ownership before the transaction. Do not delete the obstruction automatically. Bind the resume destination's own material and preserve conflict state, rather than treating the old checkpoint manifest as authority to overwrite later bytes.

**Necessary controls:** real temporary Git cases for ignored and untracked source distinct from evidence, source references omitted from the copied closure, file/directory collisions with the recorded base, and collisions introduced by the new resume base. Check original bytes, durable payloads, current-owner destination bytes and untouched checkpoint objects after refusal/crash. Add the corresponding sole omission mutants to the existing preservation matrix.

## Bootstrap feasibility and retained contracts

CP-8 explicitly supplies a narrow proposed exception to the earlier canonical-wrapper rule (`ADR-008:122–128`, CP lines 1035–1046). It keeps the session ROOT/non-worktree, binds an exact reviewed source candidate and canonical domain, and forbids candidate starts, release and health-as-authority. The inspected feasible call graph is target-slot lock, lifecycle lock, explicit validated metadata/native owned stop, quiescence and capacity: `_stop_backend_unlocked` → `_stop` → `_stop_owned` (`supervisor.py:1563–1564, 1192–1228`), with `_read_metadata`/`_validate_record` and `_confirm_stop_quiescence`/`capacity_census`. These readers do not themselves require a successful expected-launch fingerprint. This is source inference, not measured native success.

Do not wrap that path in `paused_backend`, `activating_from`, `_assert_backend_owned_or_stopped` or a general status/health preflight. They enter `process_state`/SF and/or start restoration (`supervisor.py:705–714, 1566–1572, 1608–1703, 2060–2065`). The implementation review must prove the actual candidate CLI takes the narrow route, rejects wrong/default/copied inventories and overrides before effects, and cannot reach starts. In particular CLI construction currently calls `Controller` immediately after inventory load (`cli.py:143–144`), and its constructor creates the selected state root (`controller.py:65–67`); the new binding preflight must precede that effect when invalid selection is required to be effect-free.

Ordinary release accepts only ACQUIRED/ACTIVE/QUARANTINED, checks clean source and ordinary containment, restores the counterpart, unlinks the lease, then reconciles (`controller.py:725–757`). `_is_absorbed` consults integration/base refs only (`759–794`). Keep it unchanged; a rescue ref must not satisfy release/acquire containment. READY_TO_ABSORB work continues through normal absorption. Separate canonical release avoids nonreentrant lock recursion and may start a counterpart (`supervisor.py:1678–1703`); its return/FREE cannot substitute for subsequent resource census.

The journal can remain transaction state referring to the existing lease and process registry. Implementation must define a stable generation binding from actual lease identity, with explicit expected byte transitions for quarantine/heartbeat; current acquire records owner and acquired_at, while save_lease can update heartbeat (`controller.py:326–340`, `state.py:415–428`). Do not infer generation from owner alone or compare every later phase to pre-quarantine bytes. Durable transition publication must include directory durability: existing atomic/exclusive JSON helpers differ from the existing durable publication primitive (`state.py:80–135`), so helper names alone do not establish the required barrier. These are implementation obligations already implied by CP, not reasons to create another framework.
