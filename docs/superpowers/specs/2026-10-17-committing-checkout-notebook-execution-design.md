## Public protocol

Entrypoint remains `scripts/pre-commit-notebooks.sh`. Supported callers are ordinary primary or linked worktree Git pre-commit contexts, including detached linked checkouts, a shared chain that has already changed to primary, and symlink invocation. An incoming nonempty GIT_DIR is mandatory; relative GIT_DIR is accepted only for an ordinary primary; linked GIT_DIR must be absolute. This does not recover an original target if the caller has destroyed its identity. Such a caller must preserve/provide correct Git context; ROOT owns that installed transition. A supplied GIT_WORK_TREE must be absolute and match the validated target. Relative linked/alternate index paths refuse rather than being reinterpreted after cwd changed. An absolute alternate index is preserved and fingerprinted. Bare, unborn, broken backlink, conflicts, missing index and mismatches refuse with exit2. A valid empty staged-notebook population exits0 without a scientific interpreter or kernel.

Enumerate `git diff --cached --name-only --diff-filter=ACM -z --` in the active normalized context, select names ending `.ipynb`. Retain current rename/deletion policy (ACM), no new index-snapshot semantics. NUL decode with filesystem encoding preserves spaces, tabs and newlines. Use literal pathspecs for individual filenames. Resolve/check selected files inside checkout; refuse symlinks and missing/irregular files. Refuse actual working-byte differences from active-index blobs for selected notebooks and tracked src; staged changes themselves are valid. Quiet-diff exit status 1 can reflect stat-cache suspicion even when working and index blob bytes match; it is not sufficient evidence of partial staging. Captured diff queries still admit only statuses 0 or 1. Before any notebook driver runs, the existing full working-byte comparisons against the active index blobs decide source/notebook staging equality; a true byte difference refuses even when diff reports no difference. This changes neither raw-index preservation nor the selected working-file execution semantics. Selected tracked source and notebooks must also match their active-index regular-file mode. A literal NUL-delimited ls-files --stage query supplies unique stage-zero 100644/100755 records; the working owner-executable bit determines the corresponding regular-file mode. Missing, duplicate, nonzero-stage, symlink/gitlink or mismatched records refuse before execution. Mode consistency is explicit even when repository configuration ignores executable-bit changes; modes are fingerprinted through execution alongside bytes. No repository configuration is read or changed to relax this predicate. The active index is bound by its raw SHA256 immediately after target validation and before the selected-index query or staged-name enumeration. Every subsequent captured Git helper query checks that bound digest before and after the command, including failed queries and an empty notebook selection. Captured helper commands use `git --no-pager -c diff.autoRefreshIndex=false` so diff inspection does not refresh the selected index stat cache. This command-local setting neither changes persistent configuration nor waives raw-byte equality. The original bound digest remains the reference through blob equality and execution; any index-byte change refuses acceptance without restaging or replacing the index. This is a serialized checkpoint guard, not a race-free malicious-filesystem claim. Hash tracked source working bytes and selected notebook bytes before execution and after. These hashes and HEAD identify the finite state observed; no full-tree readiness or arbitrary-data-input fingerprint is claimed.

## Execution binding

Require SKEFT_NOTEBOOK_PYTHON absolute, existing and executable only for nonempty notebook population. No auto discovery or creation of a venv. It must point at the exact ROOT-admitted existing environment. An isolated no-site python3 -I -S -B bootstrap resolves context; it does not import project or scientific packages. The selected driver runs `-I -B -X pycache_prefix=<driver-prefix> -c`, imports the existing nbformat/nbclient/jupyter_client, creates an ephemeral private-name kernelspec with `argv=[selected,-I,-B,-X,pycache_prefix=<kernel-prefix>,-m,ipykernel_launcher,-f,{connection_file},--HistoryManager.hist_file=:memory:]`, and passes its KernelManager explicitly to NotebookClient. Source/cell execution, packages and filesystem access occur only in ROOT's later admitted runtime interval.

Transient first and last guard cells insert candidate sys.path, establish actual executable/prefix, verify canonical imports, verify all loaded src module files/search paths lie within candidate and loaded source files belong to the trackedsrc list, and emit origin JSON files in the unique run directory including actual history_file, required to equal :memory:. The custom kernel receives --HistoryManager.hist_file=:memory: explicitly; this does not replace IPYTHONDIR/profiles/startup or guarantee no filesystem side effects. The driver compares observed context, writes actual output/receipt and fails closed on missing guard output. Notebook originals are read from the previously fingerprinted working file and not saved in place. The guard checks real imported origin and surrounding bytes, not all external packages or every dynamic operation between guards. No physical/model proof follows.

The driver executes once. Missing dependency/kernel startup error, cell error, timeout or origin mismatch exitsnonzero; the bootstrap retains stdout/stderr, notebook when available and failure receipt and prints one diagnostic. It does not run nbconvert again. Unique run directories eliminate the shared output-name collision. Artifacts retained on both outcomes; ROOT copies/cleans them through the existing evidence interval, never silently deletes a failure. Script remains read-only for source, active index and validation cache; numerical notebook code's own side effects remain subject to the separately admitted runtime scope, not sandboxed by this hook.
