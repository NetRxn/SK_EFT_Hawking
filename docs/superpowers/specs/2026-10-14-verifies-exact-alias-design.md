# Exact-name module-alias exclusion

Status: accepted specification; implementation and focused verification occur in the isolated candidate. Independent whole-candidate review, normal integration, finding closure and full project gates remain required. This repairs the existing ADR-009 Deferred item 7 mechanism.

## Orientation and measured defect

At public `c7d35a49252d2253e8a113ab88e035709aa58958`, `extract_verifies_edges` in `scripts/build_graph.py` first resolves Formula, then Parameter, then Lean references. The Lean branch accepts exact `lean:{raw}` membership before checking whether a bare fallback reference is a Python module alias. This bypasses the documented alias-root rule for exact bare and exact dotted matches.

The independent source assessment `round43-verifies-exact-alias-source-assessment-r1.json` and ROOT intake `round43-verifies-exact-alias-assessment-root-intake-r1.json` pin the actual source, frozen full-test counterexample and AST attribution. The frozen full run reports existing `lean:pi` edges from tests that import `parked_items as pi`. The canonical `pi` is a genuine LeanDef of type `Real → Real`; its full dictionary and the relevant Python inputs are byte-identical to the earlier integration baseline. Do not delete or rename this declaration. The per-file import model intentionally records `ast.Import` roots, including function-local imports, and excludes `ast.ImportFrom`. No scope-aware binding analysis is added.

The existing slow live guard has a separate attribution weakness: it treats any same-tail alias reference as evidence against a deduplicated edge, even when a different genuine reference supports that edge. Correctness requires at least one valid supporting reference for an emitted Lean edge. A disallowed reference must not invalidate a genuinely supported edge, nor justify an unsupported one.

Existing consumers include `last_modified.py` VERIFIES freshness propagation and graph coverage readers. The computation-readiness gate follows Formula targets. No unmeasured readiness improvement is claimed. Existing queued groups `review:2026-08-15-d8-stage10-redraft:D8:1.7` and `review:2026-08-12-adr010-queue:adr010-queue:6` also name `scripts/build_graph.py`; reserve this file for this package during implementation, leave their other requirements open, and reconcile through the existing planner rather than creating another queue.

## Decisions

**D1 — Preserve resolution priority.** Formula and Parameter resolution run unchanged. Only after they miss does Lean resolution reject a raw reference whose first dotted component belongs to that test module's recorded aliases. This rejection precedes **both** exact membership and bare short lookup. Among allowed references, exact membership remains first; fallback is allowed only for undotted names and retains the existing ambiguity behavior. Deduplication, missing-node handling, typed Lean targets and `test_kind` stay unchanged.

**D2 — Preserve legitimate names.** An exact unqualified Lean name with no module-alias collision remains valid, including a from-imported symbol. A genuine fully qualified Lean name remains valid when its root is not a recorded Python module alias. An exact bare match still wins over an otherwise ambiguous short-name index. Dotted tails never become short candidates. No special `pi` blacklist or change to the shared `_resolve_lean_short` helper.

**D3 — Correct the existing guard's evidence attribution with the complete resolution semantics.** A raw reference supports an emitted Lean target only if it first misses the actual Formula and Parameter indexes, then is outside module-alias roots, and resolves to that same target. Earlier-index selection blocks Lean fallback even when that earlier target is absent from `node_ids`: production drops that raw reference at final membership checking rather than falling through. Formula matching includes its exact bare and allowed-qualified forms; Parameter matching retains actual full/tail precedence and input order.

For references that reach Lean, exact `lean:{raw}` graph membership wins and must equal the edge's target. Otherwise only an undotted raw reference can support the target, with exactly one candidate in the **actual in-graph** short-index sequence equal to that target; preserve candidate multiplicity and ambiguity behavior. Full-catalogue ambiguity alone is not the predicate. An edge is unsupported only if no raw reference meets these conditions. A wrong-target same-tail reference never supports it.

Keep this test-local and independently specified; never call the production edge resolver or `_resolve_lean_short` to manufacture expected support. Table-driven controls must include bare Formula priority, allowed-qualified Formula priority, Parameter priority, absent earlier target, filtered graph ambiguity, exact-over-ambiguous precedence, wrong-target same-tail, a genuine+alias mixed reference and all-invalid support. In particular, refs `bad.foo` and `foo`, alias root `bad`, exact node `lean:bad.foo` and an earlier `formula:foo` or `param:foo` must not let the latter reference launder the alias-generated Lean edge. The old oracle's false-red mixed-supported case is distinct from the old resolver's exact-collision red; record the reason each baseline regression fails.

**D4 — Keep production evidence nonvacuous.** Before changing the extractor, add meaningful tests for exact bare alias collision and exact dotted alias-root collision and record their failure on the baseline. Positive controls cover matching unaliased strings, real from-import classification, qualified Lean references, Formula/Parameter priority and exact-over-ambiguous behavior. Add a mixed-reference case that would expose the old live-guard false attribution. Existing short/dotted/ambiguity tests stay active.

Capture all Lean edge dictionaries and every raw reference's priority/support/rejection disposition, exact/short/dotted/alias classification and each added/removed edge's explanation. Compare complete non-Lean edge multisets, including field values and multiplicity. Do not use regression-test additions or source-roster changes as evidence of resolver effects. Attribute final-candidate versus base changes, new regression files and seeded files separately.
