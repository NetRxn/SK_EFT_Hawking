# Existing-ratchet maintenance plan

[Design](../specs/2026-10-15-qa-zero-headroom-design.md) and [focused finding](../../../papers/AutomatedReviews/2026-10-15-qa-zero-headroom/infra.md) precede implementation. ROOT is the shared registry, closure and integration writer; the publication worker receives an exclusive ordinary Python candidate and test interval. No Lean slot, cache, dependency, census writer or scientific manuscript work is allocated.

1. Reconcile the actual finding ID and existing planner group; preserve unrelated findings. Recheck current owner hashes, real populations and clean seed journal. Return drift to ROOT.
2. ROOT applies only the exact shared-constant patch and existing test docstring adjustment. All other constants and executable tests stay exact.
3. The assigned worker runs the four existing finding verification nodes, capturing actual production input paths, populations, red checks, exact restoration bytes/mtime, registry reload, restored checks and journal state. Use existing journal APIs; no new permanent harness or mirrored tests.
4. ROOT accepts fresh independent whole implementation/effects review, applies the supported closure writer to this actual finding only and integrates through normal Git/PR discipline when applicable gates permit. Scoped checks and a closure record do not assert whole-tree or publication acceptance.

The original failed measurements/review, raw-index exceptions and current broader project failures remain preserved. Neither an unrelated detector finding nor any scientific frontier target closes with this maintenance.
