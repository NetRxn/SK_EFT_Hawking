# Surface inventory — DERIVED, do not hand-edit

> **Answers:** **How many** of anything — checks, gates, hooks, agents, commands, node/edge types, registries, bundles
>
> Generated by `scripts/architecture_inventory.py`. Each table's VALUES are read from
> the artifact that owns them — the check registry, the gate roster, the plugin manifest,
> the AST of the graph builder, the bundle registry. Their MEMBERSHIP is derived the same
> way, with one exception: the registries table lists a curated set named in the
> generator, because which collections count as tracked registries is an editorial call,
> not a mechanical property. **Do not edit this file**: run
> `uv run python scripts/architecture_inventory.py --write`.
>
> The narrative that explains how these pieces fit together is
> [`END_TO_END_MAP.md`](END_TO_END_MAP.md). This file is the *census*; that one is the
> *story*. They are split because the story is stable and the census is not, and a
> stale count inside a narrative is how this project has repeatedly lost its own map.

**No timestamp is recorded here on purpose** — a date would make the file dirty on
every run and turn the freshness check into noise. The tree state IS the timestamp.
