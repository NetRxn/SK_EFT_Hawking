## Decisions (proposed)

D1. Extend only the existing public notebook script, existing notebook tests and topology. No new check, roster, ledger, persistent validation cache, workflow or private dependency. This source proposal remains uninstalled pending independent review and the lead's allocated installation.

D2. Use an existing `python3 -I -S -B` solely as an isolated no-site stdlib bootstrap. Read the incoming Git context without clearing/switching its active index; derive the absolute Git/common directories. For an ordinary linked checkout, validate its administration-directory worktree backlink and reciprocal `.git` pointer. For a primary, require an ordinary `.git` directory. Reject unsupported/ambiguous targets, inconsistent explicit worktree roots, relative linked Git directories, relative alternate indices and unavailable metadata, including before a no-notebook result. Default index is the committing Git-dir/index; an explicitly selected alternate index must be absolute, except a primary relative index resolving exactly to its default. No cwd-only discovery may silently turn a lost linked context into primary success: inherited `GIT_DIR` is required; direct callers must supply an explicit Git context. This deliberately narrows standalone invocation rather than guessing intent. Symlink entrypoints work because script-path ancestry is not a target selector.

D3. Preserve staged-name/working-file semantics: enumerate active-index ACM paths with NUL records and select the `.ipynb` suffix, then execute those real working notebooks. Do not implement an index snapshot. Refuse selected notebook partial staging, missing/nonregular/symlink/escaping files, unresolved conflicts, unstaged tracked `src/` changes and loaded untracked/outside-checkout `src` modules. Staged canonical-source changes are allowed. Unrelated unstaged documentation is outside the receipt. All tracked `src` bytes and selected notebooks are fingerprinted before/after execution; changes refuse acceptance. The active index is bound by its raw SHA256 immediately after target validation and before the selected-index query or staged-name enumeration. Every subsequent captured Git helper query checks that bound digest before and after the command, including failed queries and an empty notebook selection. Captured helper commands use `git --no-pager -c diff.autoRefreshIndex=false` so diff inspection does not refresh the selected index stat cache. This command-local setting neither changes persistent configuration nor waives raw-byte equality. Quiet-diff exit status 1 can reflect stat-cache suspicion even when working and index blob bytes match; it is not sufficient evidence of partial staging. Captured diff queries still admit only statuses 0 or 1. Before any notebook driver runs, the existing full working-byte comparisons against the active index blobs decide source/notebook staging equality; a true byte difference refuses even when diff reports no difference. This changes neither raw-index preservation nor the selected working-file execution semantics. Selected tracked source and notebooks must also match their active-index regular-file mode. A literal NUL-delimited ls-files --stage query supplies unique stage-zero 100644/100755 records; the working owner-executable bit determines the corresponding regular-file mode. Missing, duplicate, nonzero-stage, symlink/gitlink or mismatched records refuse before execution. Mode consistency is explicit even when repository configuration ignores executable-bit changes; modes are fingerprinted through execution alongside bytes. No repository configuration is read or changed to relax this predicate. The original bound digest remains the reference through blob equality and execution; any index-byte change refuses acceptance without restaging or replacing the index. This is a serialized checkpoint guard, not a race-free malicious-filesystem claim. This is a serialized checkpoint contract, not a race-free malicious-filesystem proof.

D4. A nonempty notebook set requires ROOT's explicitly selected absolute existing executable in `SKEFT_NOTEBOOK_PYTHON`. The variable selects an executable; it grants no admission. ROOT must separately admit its existing environment and dependencies. No `uv`, dependency synchronization, install, environment repair or persistent kernel registration. Run the selected driver in isolated Python mode; generate a unique temporary kernelspec whose argv uses exactly that interpreter in isolated mode, and a kernel connection file under the same unique run directory. The custom kernel explicitly receives --HistoryManager.hist_file=:memory:, with actual start/end history observations required to equal :memory:. This narrows history persistence only; it does not replace IPYTHONDIR, profiles/startup or promise no filesystem side effects. In transient guard cells, put the candidate at sys.path[0], import the canonical constants/formulas and assert actual interpreter/prefix and every loaded `src` origin is tracked inside that checkout. Start/end observations bound this receipt; they are not a proof against deliberately hostile notebook code or a certificate for external dependency versions/physical computations.

D5. Execute each selected notebook once via nbclient with the existing120-second per-cell timeout and notebook-parent working directory. Preserve original code/narrative order between transient guards; never write guards or outputs into tracked notebooks. Each invocation has a unique OS-temporary directory for input context, kernelspec, connection data, output notebook, origin observations, stdout/stderr and receipt. Retain successful and failed artifacts and print the directory. On execution failure retain the partial notebook, print the one captured failure and exit nonzero without rerun. No shared fixed filename, shell word splitting or missing-file continuation. Runtime artifacts have separate lifetime/cleanup ownership; the script does not edit source/index or shared validation caches.

D6. Correct topology to distinguish notebook failure/refusal on every branch from the sync arm's fail-open/main-oriented policy. Existing protective chain, sync behavior, no-CI fact, wave/submission gates and main authority remain. Public candidate source does not establish that an installed chain invokes it. ROOT must coordinate the actual installed transition privately and observe the real notebook-bearing normal checkpoint without a bypass.

D7. Required evidence is layered: source/static replay; independent adversarial and separate intent review; future real-Git command-spy fixture tests; a separately admitted actual candidate journaled red/exact-byte-and-mtime restore/green; real interpreter/kernel/source origins and normal commit/required canonical gates. ## Alternatives and consequences

Copying sync's linked skip loses execution. Using cwd or script location guesses the target. Reusing the all-notebook checker would expand population/cache writers. Continuing `uv run` implicitly permits environment work. An index-snapshot execution tree adds a second engine and changes existing semantics. All are declined. Explicit existing-interpreter selection and refusal of partial staging/unsupported Git layouts impose a visible preparation step at notebook checkpoints; independent review must check that cost against the operator's intended safe cadence. Source numerical work remains independent and continues under its own allocation.

Exact partial-staging predicate (PROPOSED/PILOT): compare actual selected notebook and trackedsrc working bytes with their active-index `:0:path` blobs, in addition to ordinary Git diff checks. This detects working differences even when Git stat/assume-unchanged optimizations suppress a diff. Blob comparison is a read-only equality check, not index-snapshot execution. Proposed fixtures include this hidden-working-change case and byte drift during a spy call.
