## Explicit direct-input boundary

The supported form is a literal executable control sequence `\input` with one literal braced path `{tables/<relative-name>}` (with optional whitespace before the opening brace and an omitted or explicit `.tex` suffix), in the active draft text. Inline math, ordinary grouping and a preceding `\protect` remain supported: D12 already uses all three, so a standalone-line or brace-depth-zero rule would omit real inputs. Comment text, escaped backslashes, verbatim spans/environments, macro definition bodies and known inactive conditional branches supply no executable inputs and must never trigger a read or count toward coverage. Use synthetic controls for each. Keep inherited macro declarations for the theorem tokenizer separate from input discovery. A live macro that hides a table input, a table-like input with a computed path, or a table input in a conditional whose activity cannot be decided is outside the supported literal grammar. Where the source exposes such an ambiguous table input, return an explicit coverage failure or unmeasured result and do not read it. A literal eligible path that cannot be read safely also fails closed. This is direct-literal coverage on the audited publication source population. Arbitrary macro expansion, dynamic input paths, arbitrary conditionals, nested inputs and TeX execution are outside that claim. A structurally inactive decoy is neither a table dependency for this check nor proof that any out-of-scope reference is covered.
