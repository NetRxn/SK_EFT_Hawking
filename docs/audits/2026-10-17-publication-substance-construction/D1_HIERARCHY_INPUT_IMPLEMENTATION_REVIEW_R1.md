## Blocking inactive-input counterexample

The reader finds a canonical input by searching within the complete
float. It does not require that token to be the direct post-label body.
I seeded the actual composed D1 manuscript with an inactive input using
the repository journal. For each mutation I ran the checker and
compiled the actual paper with the same generated artifact available.
The active control rendered the distinctive Steinhauer data row.
The following changes kept all 13 details green but removed that row.

- After the label, wrap the only input in an iffalse branch or an
  unused macro definition. Both mutations compile successfully.
- Start the false branch or unused macro before the label and close it
  after the input. Both mutations compile successfully.
- Place a command redefinition before the label using
  `\expandafter\def\csname input\endcsname#1{}`. The generated input
  text is unchanged after the label. The paper still compiles and the
  row is absent. A post-label-only lexical recognizer also accepts it.
- Wrap the entire float in an iffalse branch. The scoped numeric gate
  still passes and the paper compiles without the data row. This is
  outside a recognizer confined to the labelled float.
- Escape the post-label command as a TeX line break plus text. The
  reader passes. This particular full-paper variant fails compilation.

The exact readback is in [exact-tex.log](exact-tex.log). All seeded
