### 1.1 — 🟠 Explicit null roster takes the missing-field compatibility fallback

- **Severity:** major
- **Lane:** infra
- **Location:** `scripts/lean_slots/state.py::Inventory.allowed_clients`; `tests/test_adr018_roster_validation.py` (repair regression target)
- **Gate:** ADR-018 implementation acceptance before live Gate A
- **Verify:** `uv run python -m pytest tests/test_adr018_roster_validation.py tests/test_adr018_chat_client.py -q`

**Requirement.** ADR-018 specification S18-1 requires a nonempty array for a declared admission roster. The schema-1 compatibility exception applies only when `server.allowed_clients` is absent, never to a present malformed value. The existing inventory property remains the single admission authority; no new mechanism is required.

**Evidence.** At the target head the property reads `server.get("allowed_clients")` and takes the legacy fallback when that value is `None`. Both an absent key and an explicit JSON null reach this branch. An otherwise valid schema-1 inventory with `server.allowed_clients: null` therefore produces the legacy client pair instead of a validation error. Existing tests cover missing, empty, duplicate, malformed-name and non-string-member cases, but not an explicit null roster.

**Impact.** Malformed explicit configuration can restore legacy admission rather than fail closed. This finding does not assert that arbitrary unknown clients are admitted or that a live unauthorized dispatch occurred.

**Required repair.** Select fallback by key absence, then validate every present value through the existing nonempty-array/member checks. Preserve schema-1 missing-key compatibility exactly. Add artifact-seeded regression tests writing an actual inventory JSON file and calling `Inventory.load`, including null and neighboring invalid scalar/object values, both authentication modes, valid missing-field fallback, explicit narrow opt-in and immutable return controls. The parser tests need no slot, supervisor, Lean, MCP, network or build.

**Disposition at filing.** Open; source-inspected failure, not executed. Implementation may be repaired under the already accepted specification, but test execution and properly independent re-review are still owed. Formal closure remains through the project-owned single writer; this author file must not self-mark the finding fixed.
