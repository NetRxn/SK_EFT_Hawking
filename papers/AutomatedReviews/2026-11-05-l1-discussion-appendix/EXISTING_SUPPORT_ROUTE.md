## Supplements, includes, and placement limits

A separate supplementary TeX/PDF can be manually read, but the existing L1 contract inspected here does not give it the same automatic compile, length, and independently bound single-source catalog coverage. The canonical compiler `scripts/compile_bundle_pdf.py:203-228` selects only `bundle_dir / 'paper_draft.tex'`; the canonical length measure `scripts/validation/checks/bundles_readiness.py:1915-1970` selects only `paper_draft.tex` and `paper_draft.pdf`. An unreferenced standalone supplementary PDF is not measured by that L1 route. Do not adopt a separate artifact merely because flexible JSON metadata can mention it.

TeX input closure IS supported for compile freshness and certain prose gates: `scripts/validate_helpers.py:400ff` resolves `\\input`/`\\include` recursively and figures/bibliography; `scripts/validation/checks/bundles_readiness.py:825-860` defines reader-visible sources from the TeX closure. This does not mean a claimswalker automatically expands input files: the claims-reviewer is a manual protocol, and sentence_state/graph ingestion consume catalog JSON. Fragment compilation is supported, but fragment-aware line/quote binding has no automatic support in the reviewed claims writer. Keeping moved prose in the actual manuscript avoids introducing that extra binding convention.

An appendix after bibliography would remain prose under the manual reviewer's all-sections instruction and would compile if placed before end-document, but is NOT fully covered by existing style gates. In particular `bundle_sentence_length`, `scripts/validation/checks/bundles_readiness.py:1660-1678`, truncates each source at `\\begin{thebibliography}`. It would miss any same-file appendix after that marker. Therefore place the appendix BEFORE bibliography. Existing precedent: `papers/D3/paper_draft.tex:2568` has `\\appendix`, appendix sections follow, and bibliography begins at line 2751.

The entire compiled PDF counts for L1 manuscript length. `scripts/validation/checks/bundles_readiness.py:1915-1970` calls pdftotext on the whole current PDF and adds 300 per main-file figure for word-equivalents; it does not subtract appendix or references. `papers/L1/bundle_metadata.json:108-119` declares a 3750 word-equivalent ceiling and 600-character abstract ceiling (the abstract source is explicitly unverified). No change to those limits is authorized or proposed here. Appending audit material may breach the existing ceiling; actual compile/length evidence must decide that after editing. Moving material cannot be claimed as satisfying the length gate in advance.
